# Diff against the established state of each Finding, not the previous Report

A Watchlist Run is diffed against a Baseline that holds the latest established value of each Finding, with the provenance and date that established it, rather than against the previous Report. Report-to-report comparison is simpler, but it treats "absent from this Run" as "removed" and lets a Run that merely failed to reconfirm a fact overwrite it. For example: Report A establishes a price of $100/month. Run B finds no pricing, so under report-to-report comparison B would either raise a false "removed" Alert or, as the new Baseline, erase the $100. Then Run C finds $130 and would see no change, or a new fact instead of a change. With per-Finding state, B leaves the price Not reconfirmed at $100 with no Alert, and C raises $100 → $130. Removal therefore needs affirmative evidence: a fresh replacement value for a single-valued predicate, or an explicit negative Finding. Only Sources fetched in the current Run can establish, change or retract a Finding. Prior Reports are background only, so a Watchlist Run cannot confirm its own history. A Finding is identified by subject, predicate and scope (plus object for multi-valued predicates) but not by its As-of period, so values are compared across time. An older value never replaces a newer established one, and a value whose period is unknown is flagged as ambiguous rather than raised as a change.
